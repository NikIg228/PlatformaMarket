# Поддержка в кабинетах клиники и поставщика

Актуально: 06.10.2026. Маршруты `/clinic/support` и `/supplier/support` используют
единый экран `apps/web/app/workspaces/support.tsx` и существующую операторскую очередь.
Доказательства и ограничения: [SUPPORT-UX](../governance/task-state/SUPPORT-UX-2026-10-06.md).

## Интерфейс

- При отсутствии обращений доступна компактная форма: категория, тема, описание.
  Тема требует 4–200 символов, описание 10–10 000; ошибки показываются возле поля.
- При наличии истории — список и переписка; поиск по теме/номеру и статус
  применяются на сервере до пагинации. Пользовательский список сортируется по
  последней активности; старые обращения подгружаются при прокрутке, также
  доступна кнопка для клавиатуры. Операторская сортировка очереди сохранена.
- Список и переписка занимают доступную площадь страницы без внешней карточки.
  Компактная шапка содержит тему, категорию, номер и статус. Подтверждение отправки
  появляется только после успешного действия, закрывается крестиком или через
  6 секунд и не занимает место в потоке переписки. Кнопок Reload нет.
  Поле ответа без видимой подписи автоматически растёт до 160px; доступное
  название сохранено. Скрепка и текстовое действие «Отправить» находятся внутри поля;
  форматы и лимиты файлов доступны в подсказке и для экранного диктора.
- `ticketId`, `mode=new`, `q`, `status` отражаются в URL. На телефоне список и
  переписка отображаются отдельно. Назад/вперёд восстанавливают выбранное обращение.
- Сообщения подписаны «Вы», «Сотрудник организации», «Поддержка». Внутренние
  заметки не выдаются пользователю. Существующий связанный диалог доступен ссылкой.
- Активная переписка обновляется каждые 15 секунд, список каждые 30 секунд,
  только при видимой странице; есть ручной повтор и восстановление после offline.
  Подгруженная история сохраняется. Новое сообщение не сбрасывает позицию чтения:
  при чтении ранних сообщений появляется кнопка перехода к новым.
- Черновики и неопределённые результаты отправки сохраняются в `sessionStorage`
  текущей вкладки, отдельно для организации и сессии; восстановление ограничено
  8 часами. При недоступном хранилище остаются память страницы и предупреждение
  об уходе. Текст, метаданные загруженных вложений и ключ повторной отправки
  удаляются после подтверждённого успеха. Содержимое файлов в sessionStorage
  не записывается; неотправленные загрузки доступны для привязки в течение часа.
- После завершения обращения обычное поле отправки заменяется действием
  «Вопрос не решён». Пользователь вводит уточнение и явно отправляет его вместе
  с повторным открытием. Скрытых коммерческих операций при этом нет.

## Контракты и инварианты

- `GET /support/tickets`: дополнительные необязательные `q` (до 200 символов)
  и `sort=recent|queue`. Старый вызов без `sort` сохраняет операторский порядок.
  Tenant-фильтр применяется вместе с поиском и статусом до `skip/take`.
- `SupportMessage` в истории дополнен необязательным `authorLabel`; старые клиенты
  совместимы. Содержание внутренних заметок не участвует в пользовательской истории.
- `POST /support/tickets/:ticketId/messages`: необязательный boolean `reopen`.
  Для публичного сообщения в `RESOLVED/CLOSED` требуется явное повторное открытие.
  Оно переводит обращение в `IN_PROGRESS`, очищает `resolvedAt/closedAt` и назначает
  срок по существующей политике приоритета. Оператору дополнительно требуется
  `support.ticket.manage`. Внутренняя заметка не открывает обращение.
- Сообщение, версия обращения, audit, outbox и результат идемпотентности фиксируются
  одной транзакцией с блокировкой строки. Повтор команды не создаёт второе сообщение
  или событие. Клиент сохраняет исходный `reopen` при повторе неопределённого результата,
  даже если обновление уже показало активное состояние обращения.
- Создание уведомляет организацию заявителя и операторские организации.
  Публичный ответ создаёт `SupportTicketUpdated` с `action=MESSAGE|REOPEN`: ответ
  оператора направляется организации заявителя, ответ пользователя — операторам.
  Текст сообщения не копируется в событие/уведомление. Внутренние заметки не создают
  внешнего уведомления. Существующие настройки каналов и отказа от уведомлений
  сохраняются; запись outbox сама по себе не доказывает фактическую доставку.

## Границы

Рабочая БД, схема Prisma и внешние каналы не изменяются. Операторский интерфейс
дополнен чтением/скачиванием вложений. Персональный постоянный счётчик непрочитанных
обращений остаётся отдельным сценарием. Индикатор новых сообщений текущей
переписки не является таким счётчиком.
Номер заказа можно указать в описании; новый picker связанных заказов/товаров
не добавлен. Значение SLA не выдаётся за обещание времени ответа или решения.

## Вложения — 06.10.2026

- Клиника и поставщик могут приложить до 10 файлов по 10 MB (10 000 000 байт)
  к первому обращению и каждому ответу: PNG, JPG/JPEG, PDF, Word DOCX, Excel XLSX.
  Старые DOC/XLS, макросные форматы и произвольные архивы не входят в список.
- `POST /support/attachments` (`support.ticket.create`) принимает `fileName` и
  `contentBase64`, возвращает `assetId/name/contentType/sizeBytes/expiresAt`.
  Большой JSON разрешён только этому upload POST (как загрузке документов),
  а не всем support-операциям. Декодированный файл ограничен 10 MB на сервере.
- Используются существующие private storage, проверка сигнатуры/расширения и
  карантин/scanner. Production требует включённый AV; локальный профиль может
  использовать существующий disabled-mode. UI не выдаёт загрузку за AV-сертификацию.
- Создание обращения принимает необязательные `attachments`; ответ принимает
  текст и/или вложения. Пустое сообщение без файлов отклоняется. Имя/тип/размер
  берутся из UploadAsset, а не из пользовательского описания ссылки.
- Чистый support-файл может атомарно привязать только загрузивший его пользователь
  той же организации, один раз, до истечения часа. Привязка, сообщение, audit,
  outbox и идемпотентный результат находятся в одной транзакции. При откате файл
  снова доступен для повтора; другая команда не может повторно использовать его.
- `GET /support/tickets/:ticketId/messages/:messageId/attachments/:assetId`
  (`support.ticket.view`) сначала проверяет доступ к обращению и видимость
  сообщения, затем его ссылку и чистый привязанный asset. Внутренние заметки
  оператора и их файлы недоступны клиентам. Ответ — binary attachment с
  `private, no-store` и `nosniff`, без публичного storage URL.
- Пользователь видит загрузку, ошибки, повтор/удаление выбранного файла, имя и
  размер. Отправка блокируется до завершения загрузок и устранения ошибок.
  Изображения открываются в диалоге; остальные файлы скачиваются для просмотра
  в привычной программе. Повреждённое изображение даёт понятную ошибку просмотра.
  Извлечение текста, анализ содержимого и конвертация документов не выполняются.
- Удаление из черновика убирает ссылку; неотправленные объекты очищает почасовая
  задача SupportAttachmentsService после истечения часа. Удаление и привязка
  используют взаимоисключающий conditional claim; сбой хранилища оставляет
  маркер для следующего повтора очистки. Отправленные вложения не затрагиваются.
