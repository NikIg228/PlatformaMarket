# Manual supplier runbook

1. Проверить организацию, полномочия владельца и акцепт опубликованной версии общих условий и отдельный допуск оператора
   (Product §9.7 / ADR013). Пустые DRAFT не принимаются; legacy подписанные
   договоры сохраняют свои проверки. Новые две ЭЦП не требуются.
2. Создать 20 товаров/offers, заполнить упаковки, минимальную партию, цену, остаток и склад.
3. Выполнить массовое изменение цены, остатка и публикации; проверить audit log.
4. Создать контрольный заказ, подтвердить его поставщиком и проверить резерв.
5. При расхождении снять публикацию, указать причину, исправить данные и повторить действие идемпотентно.
6. Сохранить время до первого offer/заказа и evidence в Connector Readiness Registry.

## Редактирование существующего предложения

В инспекторе «Товары» меняется цена; ссылка «Обновить остатки» открывает
«Остатки» с выбранными предложением, складом и балансом, готовым к изменению.
В таблице остатков доступна такая же форма через «Изменить остаток».
Вводится фактическое количество до вычета резерва и страхового запаса.
Цена и публикация при этом не меняются. Подключённые источники, заблокированные
и архивные предложения не допускают ручного сохранения через эту форму.

Типизированные PUT `/suppliers/:supplierId/offers/:offerId/commercial/stock`
и `/commercial/price` требуют соответственно `inventory.adjust` и
`pricing.manage`; просмотр использует существующее `catalog.product.view`.
Первый принимает только количество, второй — только цену/НДС, плюс склад,
ожидаемые версии offer/balance и idempotency key. Чужие поля дают 400;
устаревший снимок — 409 с явным сравнением перед новым сохранением.
Неизвестный результат повторяется с прежним ключом и payload.
Резерв и страховой запас сохраняются; история цены, audit/outbox и баланс
меняются только соответствующей доменной операцией. Совмещённая команда
`/commercial` сохранена для первоначального заполнения предложения.

Целевая проверка без запуска остальных PostgreSQL-сценариев:
`npm run db:test -- exec -- node scripts/verify-postgres-integration.mjs --commercial-only`.
Перед ней нужны актуальные сборки schemas/API. Используется только test DB;
проверка включает HTTP-контракты, права, tenant isolation, rollback, replay,
версии складов и конкурирующие записи, с удалением созданных fixtures.
