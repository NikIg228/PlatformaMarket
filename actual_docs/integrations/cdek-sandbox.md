# СДЭК: учебный расчёт в заказе Market

Поручение владельца 17.11.2026. [Evidence](../governance/evidence/cdek-sandbox-20261117.md).
Договор и личный кабинет созданы по сообщению владельца; при осмотре ЛК
подтверждено отсутствие ключей интеграции. Боевые ключи для песочницы не нужны.

## Уточнение технического задания по ответу СДЭК — 22.11.2026

[Источник, полный разбор восьми ответов и границы проверки](../governance/evidence/cdek-response-20261122.md). Нумерация ответа не полностью совпадает с черновиком вопросов: сопоставление выполнено по смыслу. Текст ниже задаёт уточнённые требования, а не сообщает о новых изменениях кода. Старые evidence сохраняются в своей версии.

### Создание, сверка и отмена

СДЭК сообщил о невозможности создать второй заказ с тем же номером отправления ИМ; рекомендует сверку по im_number. Обычно создание занимает около секунды, но это не гарантированный срок. Сохраняем стабильный номер Market, локальную защиту от дублей и проверку принадлежности. При timeout/INVALID сначала поиск по im_number; отсутствие через секунду не означает окончательный отказ и не разрешает новый номер/повторную услугу. Подтверждённые UUID/трек не подменяются. Текущая реализация этой сверки согласуется с рекомендацией; внешний дефект UUID не объявляется устранённым СДЭК.

Для отмены менеджер рекомендует поиск по im_number или cdek_number. Он не указал точный terminal status, код ответа, срок видимости и правило различения удаления/задержки. Поэтому наш sandbox-признак исчезновения по UUID и треку остаётся наблюдаемой эвристикой, не production-контрактом. Ошибка поиска сама по себе не подтверждает отмену. Текущая sandbox-реализация не меняется этой документацией.

### Цена и допуск к боевой схеме

Marketplace-интеграции доступны только в РФ по ответу менеджера. До подтверждения применения конкретного договора Platforma в KZ с разными отправителями/складами production admission остаётся незакрытым; наличие обычного API не означает разрешение этой схемы. Перед перевозчиком плательщик — договор используемых ключей.

Калькулятор с нашими ключами возвращает договорные цены; окончательная стоимость определяется при вручении, перемер возможен на любом этапе. Входные данные расчёта должны включать тариф, направление, услуги, НДС, страхование/комиссию наложенного платежа при применимости, реальный вес и размеры с упаковкой. Это требования к будущему коммерческому расчёту: текущая учебная форма поддерживает лишь описанный ниже scope. Наложенный платёж не включается этим ответом в продукт. Его валюта соответствует стране получателя; прежний вопрос о валютах cost/items_cost_currency/delivery_detail полностью не закрыт.

Требования DELIVERY-GUARANTEE/V11 не отменяются: окончательные суммы до оплаты, отсутствие обычных доплат клинике и отсутствие автоматического покрытия разницы Platforma. Ответ не обеспечивает их выполнение. Блокер и договорное решение — [V13](../OPEN_QUESTIONS.md#v13), а не новая формула в коде.

### Жизненный цикл и ответственность систем

Изменять отправление в движении через API нельзя, обращение идёт через менеджера. В будущем UI запрос Market должен оставаться запросом до подтверждения; нельзя обещать исполнение через API или менять оплаченные условия молча. Возвраты у перевозчика формируются по договору, конкретные случаи/стоимость требуют его условий. Это не автоматическое согласование возврата товара или денег в Market.

Статус СДЭК «Вручено» хранится как факт перевозчика; приёмка количества/качества, расхождения, спор и денежные действия Market сохраняют собственные правила. «Не вручено» не означает автоматически «возвращено поставщику» или «деньги возвращены». Подтверждение на сайте не влияет на статус СДЭК. Осмотр по умолчанию разрешён без услуги запрета; внутренний SMS/OTP Market не заменяет код или подтверждение СДЭК.

### Уведомления и приёмка

В sandbox нет уведомлений и реальных движений/задержек. Пуши приложения/письма СДЭК не являются webhook Market. Менеджер сослался на [описание вебхуков](https://apidoc.cdek.ru/#tag/common/Opisanie-struktury-vebhukov); доступный веб-просмотр 22.11 не отдал текст раздела. Подлинность, условия повторов, порядок, восстановление пропусков и отключение подписки не подтверждены этим письмом; конкретные параметры не выдумываются. Требуются проверка актуального контракта и отдельно разрешённая внешняя приёмка. Общие sandbox-подписки не изменять.

Предоставлены номера 1110026201 («Вручен») и 1110026438 («Не вручен»). Это справочные terminal fixtures, не доказательство доступности нашему договору; чтение сейчас не выполнялось. Не пытаться обходить недоступность чужого заказа, менять эти заказы или использовать их как evidence нашего полного цикла.

При будущей приёмке разделять:
- локальные изолированные тесты: mapping, дубли/перестановка событий, пропуски/reconcile, ошибки и запреты tenant/actor;
- sandbox: свои создание/поиск/отмена и допустимое чтение terminal fixtures; нереализуемые движения и уведомления обозначать как ограничения среды;
- отдельно разрешённые реальные проверки: webhook, доставка/вручение, возвраты/документы/итоговая цена на своём договоре. Пока NOT_RUN.

Открыты: допуск KZ-схемы и фиксация цены (V13), точная семантика отмены, контракт webhook, доступ к своим примерам возвратов, валюты остальных денежных полей, конкретные условия договора. Общие ограничения справочников/дат признаны ограничениями sandbox; рабочие примеры и полнота production для KZ не доказаны. Восемь вопросов повторно целиком не отправлять; новый запрос при отдельном поручении должен касаться только остатка. Код, активация, письма и новые provider-вызовы не входят в это обновление.

## Граница текущего модуля

Сервер использует только `https://api.edu.cdek.ru/v2`: OAuth, города Казахстана
и калькулятор тарифов. В заказе клиники/поставщика можно выбрать города,
указать вес в граммах и размеры в сантиметрах для одного места, получить
учебный расчёт и выбрать тариф для просмотра. Выбор не сохраняется в заказе.
API поддерживает от 1 до 20 мест; форма текущей версии поддерживает одно.

Нет вызова создания отправления, курьера, оплаты или передачи персональных
данных. Учебная цена всегда `payable: false`, не меняет цену заказа и не
подтверждает договорный тариф. Создание отправления, выбор конкретного ПВЗ,
адрес получателя, документы, статусы и отмена остаются дальнейшими частями R5.

## Подключение

Backend: `CDEK_SANDBOX_ENABLED=true`, `CDEK_SANDBOX_CLIENT_ID`,
`CDEK_SANDBOX_CLIENT_SECRET`. Только публичные учебные credentials из
[официального SDK](https://github.com/cdek-it/sdk2.0/blob/master/src/Constants.php).
Не помещать credentials в Git или переменные `NEXT_PUBLIC_*`.
Frontend: `NEXT_PUBLIC_CDEK_SANDBOX=true` при запуске dev или сборке.
Без флага блок не отображается. Сервер отклоняет обращения в production,
на limited stand, при отключённом флаге или отсутствии credentials.
Production activation этим runbook не разрешается.

## HTTP

Все операции требуют действующей сессии, `delivery.view` и принадлежности
заказа организации покупателя/поставщика. Чужой заказ возвращает404 до
обращения к перевозчику. Контекст организации связывается общей auth boundary.

- `GET /api/supplier-orders/:orderId/cdek-sandbox`: состояние конфигурации.
- `GET /api/supplier-orders/:orderId/cdek-sandbox/cities?city=...`: поиск города.
- `POST /api/supplier-orders/:orderId/cdek-sandbox/quotes`: учебный расчёт.

Контракты: `packages/schemas/src/cdek-sandbox.ts`, OpenAPI и методы
`cdekSandboxStatus`, `cdekSandboxCities`, `cdekSandboxQuote` в api-client.
Неверные параметры:400; нет прав:403; нет своего заказа:404;
конфигурация/ошибка СДЭК:503 `CDEK_SANDBOX_UNAVAILABLE` без тела провайдера.
Таймаут10сек на запрос, bounded response1MiB, allowlist только учебного хоста.
После401 токен обновляется один раз. Денежный результат нормализуется Decimal
в minor units; код валюты СДЭК2 означает KZT согласно официальному widget.

## Внешняя проверка

`node scripts/verify-cdek-sandbox.mjs <local-credentials.json> [receipt.json]`
принимает локальный JSON с двумя backend-переменными выше. Выполняет OAuth,
поиск Алматы/Караганды и расчёт синтетической упаковки1000г,20×20×10см.
Не создаёт заказ. Receipt содержит только результат, города и число тарифов.
Проверка17.11 вернула12 тарифов; это не проверка production-цен или отправления.

Учебный справочник может отличаться от боевого: поиск «Астана»17.11 не вернул
результат. UI показывает отсутствие города, не подставляет другой молча.
Фиксация цены, работа с адресами разных поставщиков и условия договора остаются
в [V13](../OPEN_QUESTIONS.md); общая цена калькулятора не является гарантией.
