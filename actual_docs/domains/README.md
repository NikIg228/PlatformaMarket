## Как поддерживать документы

Подробности области развиваются в её документе. README остаётся навигацией,
[overview](../PROJECT_OVERVIEW.md) — общей картиной, а
[roadmap](../MAIN_ROADMAP_TO_PRODUCTION_2026-10-06.md) — единственным checklist
исполнения. Нового параллельного backlog здесь нет. Приоритет требований сохраняет
[функциональная карта](../FUNCTIONAL_AUDIT_AND_ROADMAP_2026-10-08.md);
расхождение нужно согласовать и исправить в связанных источниках, не молча
переопределять решение локальной заметкой.

При изменении области обновлять её решения/открытые вопросы и связанные ссылки
на контракт, код, UI и evidence. Отличать: **принято владельцем**, **предложено**,
**есть в коде**, **проверено на версии**, **подтверждено внешним сервисом**.
Имя адаптера и план интеграции не являются live-приёмкой. Дата этих документов
обозначает актуализацию описания; runtime основание — принятый R0-1e666ee.
Ссылки на код — навигация, не новая сертификация. Приёмка версий остаётся в
[Matrix](../governance/PROJECT_ACCEPTANCE_MATRIX.md), решения текущего R1 —
в [карточке](../governance/task-state/R1-LAUNCH-SCOPE-2026-10-08.md).
