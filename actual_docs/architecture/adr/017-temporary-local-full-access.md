# ADR 017: временная деактивация ролей для локального просмотра

Статус: принято по решению владельца 02.10.2026; проверка реализации ведётся
в [карточке](../../governance/task-state/CABINET-UX-2026-10-02.md).

## Решение

Владелец временно отключает ролевые ограничения в кабинетах клиники,
поставщика и оператора, чтобы просмотреть существующий контент перед редизайном.
Роли и назначения сохраняются. Это временное исключение из RBAC части ADR003,
а граница platform authority из ADR006 сохраняется.

Серверный `ACCESS_CONTROL_MODE` имеет два значения:

- `FULL_ACCESS`: любой активный участник активной организации с активным
  аккаунтом получает весь зарегистрированный набор permissions. Прямые
  доменные permission filters используют ту же политику.
- `ROLE_BASED`: прежняя проверка ролей; default API, worker, CI и production.

Обычный локальный launcher выбирает `FULL_ACCESS`; явное `ROLE_BASED` возвращает
старую модель после перезапуска. Production отклоняет `FULL_ACCESS`.
Флаг серверный, не `NEXT_PUBLIC`; UI получает режим и permissions через
типизированный `GET /access-control/policy`. Старый permissions endpoint сохранён.

JWT, отзыв сессий, активная membership, tenant ownership, capability организации,
согласования закупки и состояния документов/заказов продолжают проверяться.
Клиника не становится оператором и не получает данные другой организации.

В UI управления сотрудниками отображается полный доступ, назначение ролей
скрыто, новое приглашение не требует roleIds. Создание/назначение/удаление ролей
через role-management API заморожено с409; существующие данные не удаляются.
Отключение сотрудника, отзыв сессий и защита от удаления последнего управляющего
остаются доступны и учитывают всех активных сотрудников в полном режиме.

## Последствия и проверка

Миграция и reseed не требуются. Для новых сотрудников без сохранённых ролей
после возврата `ROLE_BASED` нужно назначить роли обычным разрешённым процессом.
Полный доступ не создаёт отсутствующие бизнес-данные и не включает внешние
интеграции. Редизайн и генерация референсов — отдельная последующая задача.

Обязательны schema/client/policy tests, прежние RBAC regressions, три браузерных
сценария с реальными JWT без ролей на disposable PostgreSQL, отказы чужому tenant,
неоператору и заблокированному сотруднику; build/config/runtime и локальный smoke.
`npm run verify:full-access` запускает эти три сценария после canonical build,
через тот же изолированный DB/port preflight; gate включён в CI после verify:web.
