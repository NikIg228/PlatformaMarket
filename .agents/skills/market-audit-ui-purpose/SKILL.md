# PlatformaMarket UI Audit

Read [AGENTS.md](../../../AGENTS.md) and the task-relevant [Workflow](../../../actual_docs/governance/DEVELOPMENT_WORKFLOW.md). Preserve the current request, personal rules, existing evidence and unrelated work. Review-only requests stay read-only. A skill does not authorize new phases, delegation, live effects or another source checkout.

Use the [UI standard](../../../actual_docs/ui-ux/UI_UX_IMPLEMENTATION_STANDARD.md), [design system](../../../actual_docs/ui-ux/DESIGN_SYSTEM.md) and personal UI rules as the evaluation boundary. The audit does not authorize product fixes or new visual directions.

Identify the participant's task, each block's purpose, real backing and primary/recovery action. Trace data and copy to API/contracts, localization or approved content. Preserve useful explanations and established layouts; repetition, cards and tables are not defects by themselves.

Select representative routes and states by risk/shared impact, not a fixed quota. Inspect geometry, long values, mobile/locales, computed styles, contrast, labels, keyboard and focus. Capture and visually inspect affected-area screenshots; distinguish static observations from exercised behavior. Screenshots do not prove backend safety or full accessibility compliance.

On working data remain read-only, including avoiding actions that mark messages read or alter preferences. Mutations/fault injection need a safe isolated fixture environment within the authorized scope. Missing fixtures or browser access is an explicit coverage gap.

Report concrete findings with route/file, reproduction, impact, evidence and minimal proposal. Do not hide FAIL or untested states, fabricate scores or require an arbitrary number of redesign cycles. Implementation, if separately requested, follows the existing UI delivery gates.
