# PlatformaMarket Product Analysis

Read [AGENTS.md](../../../AGENTS.md) and the task-relevant [Workflow](../../../actual_docs/governance/DEVELOPMENT_WORKFLOW.md). Preserve the current request, personal rules, existing evidence and unrelated work. Review-only requests stay read-only. A skill does not authorize new phases, delegation, live effects or another source checkout.

Use the [documentation index](../../../actual_docs/DOCUMENTATION_INDEX.md) to locate the selected requirement in the main roadmap and its OPEN_QUESTIONS. Compare the [target contracts](../../../actual_docs/architecture/MARKET_TARGET_CONTRACTS.md) with schemas, API/client, reachable UI and evidence; a proposed state or historical PASS is not implemented behavior.

Trace a participant outcome across clinic, supplier and operator: publication/admission, discovery, price/stock revalidation, order/payment, fulfillment, documents and exceptions. Inspect only dependencies relevant to the request. Distinguish internal readiness, scoped acceptance and actual provider readiness.

Reuse closed CORE slices unless new evidence proves a gap. Recommend a minimal vertical result with dependencies and acceptance; do not start the next roadmap item. ERP self-service belongs in the participant cabinet, not a mandatory support-ticket flow. Unresolved business policy remains an owner decision in OPEN_QUESTIONS; neither code nor a newer timestamp selects it.

Report verified capabilities, concrete gaps, source locations and limits. Label inference and proposals; avoid a competing backlog.
